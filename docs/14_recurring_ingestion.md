# 비짓제주 지속 수집 운영

작성일: 2026-11-08. 이 문서는 구현된 연결과 아직 실행하지 않은 운영 작업을 구분한다.

## 현재 상태

수집 엔진, Firestore 저장 어댑터, 공개 카탈로그 연결, 인증된 예약 실행 경로와 로컬 모의 테스트를 준비했다. **실제 VisitJeju API 키는 없으며 무료 여부·정량 호출 한도·초과 과금 조건·장기 저장 조건도 확정하지 못했다. 실제 API 호출, Firestore 읽기·쓰기, 배포 또는 예약 등록을 수행하지 않았다.** 기본 화면은 기존 공개 UI 관측 자료 60곳을 계속 사용한다.

VisitJeju 공식 안내는 인증키 필수, 담당자 승인 후 이메일 발급, 과도한 트래픽의 이용 제한을 설명한다. 이를 무료·무제한 사용 허가로 해석하지 않는다. [공식 API 안내](https://www.visitjeju.net/kr/visitjejuapi), [공식 가이드 PDF](https://api.visitjeju.net/file/bbsattachment/filepath/202606/15/2f62f5a7-9d71-4d0c-a43c-54321cd4b06b.pdf)

TourAPI는 대체 자동 수집기로 연결하지 않았다. 무료라는 사실과 별개로 공식 정책에 로컬 캐싱 금지가 표시되어 저장 방식의 허용 범위 확인이 필요하다. [공식 저작권 정책](https://api.visitkorea.or.kr/#/useServiceGuide/2), [제공기관 조사 기록](../research_notes/sources/provider-access-2026-11-08.md)

## 실행 전제와 비용 승인

사용자의 상시 지침에 따라 제공기관 API, 실행 서버, 데이터베이스, 저장소, 트래픽, 예약 실행 각각의 요금·무료 한도·초과 조건·갱신 조건을 설명하고 **구체적 범위·예산·기간에 대한 명시적 승인**을 받은 뒤 활성화한다. 현재 이 승인과 비용 확인을 대신할 수 있는 설정은 없다. 자격 증명이나 기존 계정이 있다는 이유로 실행하지 않는다.

무료 API가 확인되더라도 Firebase 읽기·쓰기와 저장량, 호스팅 실행·트래픽 비용은 별도다. 현재 플랜의 잔여 무료량이나 과금 차단 방식은 확인하지 않았으므로 예상 총비용을 0원으로 보장하지 않는다. 아래 수량 제한은 호출량을 줄이는 장치이며 금액 단위의 지출 한도나 제공기관 quota를 대체하지 않는다.

| 설정 | 실행 조건 / 현재 기본값 |
|---|---|
| `CLOUD_SERVICES_ENABLED` | 서버 클라우드 접근 승인, `false` |
| `VISITJEJU_API_ENABLED` | 제공기관 호출 사용, `false` |
| `VISITJEJU_USAGE_APPROVED` | 이용 조건 및 발급 계약 확인, `false` |
| `VISITJEJU_SYNC_ENABLED` | 지속 수집 사용, `false` |
| `VISITJEJU_SYNC_COST_APPROVED` | 지속 수집의 모든 비용 범위 승인, `false` |
| `VISITJEJU_STORAGE_APPROVED` | 응답 정규화·저장·재공개 권리 확인, `false` |
| `VISITJEJU_SYNC_APPROVAL_EXPIRES_AT` | 승인 종료시각, 빈 값; 미래 UTC ISO 시각이 필수 |
| `VISITJEJU_API_KEY` | 발급된 서버 전용 키, 현재 없음 |
| `VISITJEJU_API_URL` | 승인된 HTTPS endpoint만 허용 |
| `VISITJEJU_API_KEY_PARAM` | 공식 계약에서 확인한 `apiKey` 또는 `apikey` |
| `FIREBASE_ADMIN_*` | 서버 전용 자격 증명; 존재 자체는 실행 허가가 아님 |
| `CRON_SECRET` | 32–256자 URL-safe 비밀값, `.env.local`에만 로컬 생성 |
| `VISITJEJU_SYNC_MAX_PAGES` | 실행당 최대 페이지, 기본 2, 1–2만 허용 |
| `VISITJEJU_SYNC_MAX_ITEMS` | 실행당 처리 항목, 기본 100, 1–100만 허용 |

종료시각은 `YYYY-MM-DDTHH:mm:ssZ` 또는 밀리초를 포함한 UTC ISO 형식이다. 비어 있거나 잘못된 날짜, 과거 시각이면 실행이 차단된다. 플래그는 정확한 문자열 `true`만 인정한다. 한도를 늘리거나 승인 기간을 연장하는 일은 기존 승인 범위와 별개로 검토한다.

`getSyncReadiness()`는 네트워크 접근 없이 위 설정을 검사해 비밀값 없는 blocker 코드와 실행 한도를 반환한다. 이 함수의 결과가 `ready`라고 해도 사람의 승인 기록을 생성하거나 비용을 결제한 것은 아니다. 승인 근거·범위·기간은 운영 기록으로 별도 보관해야 한다.

## 예약 진입점과 실행 한도

경로는 `GET /api/cron/visitjeju`이며 `Authorization: Bearer <CRON_SECRET>` 헤더가 필요하다. `timingSafeEqual`로 같은 길이의 SHA-256 다이제스트를 비교한다. URL 쿼리의 비밀값, 세션 쿠키, 요청의 임의 페이지·언어·한도·run ID는 받지 않는다. `HEAD`는 405로 거절하므로 상태 확인 요청이 수집을 실행하지 않는다.

| 응답 | 의미 |
|---|---|
| 401 `UNAUTHORIZED` | 인증 실패. SDK·수집 엔진에 진입하지 않음 |
| 503 `CRON_NOT_CONFIGURED` | 비밀값 없음 또는 형식 오류 |
| 503 `SYNC_NOT_READY` | 인증 성공 뒤 준비 조건 미충족. 안전한 blocker 코드만 반환 |
| 200 `completed` | 이번 조회가 마지막 페이지까지 완료됨 |
| 200 `paused` | 수량·시간 제한에 도달했고 다음 실행에서 커서부터 재개 |
| 200 `busy` / `duplicate` | 다른 실행이 진행 중이거나 같은 날짜의 실행이 이미 존재 |
| 503 `failed` / `SYNC_EXECUTION_FAILED` | 수집·정규화·저장 오류. 내부 오류 메시지·키·URL은 응답에 포함하지 않음 |

모든 응답은 `Cache-Control: no-store`다. 실행 결과에는 상태, run/scan ID, 커서, 처리 건수, 고정 오류 코드만 들어간다. 외부 오류 원문을 로그로 출력하지 않는다.

예시 예약 파일 `vercel.cron.example.json`은 매일 UTC 18:00, 한국시간 다음날 03:00의 일정을 담는다. **활성 `vercel.json`에는 이 예약을 넣지 않았다.** 예시 파일만으로 예약은 등록되지 않는다. 실제 플랫폼의 플랜별 예약 조건과 비용을 확인하고 승인받은 뒤 배포 설정에 반영해야 한다.

run ID는 `visitjeju-ko-YYYYMMDD` 형식의 UTC 날짜다. 동일 날짜의 재호출은 저장된 run ID로 중복을 차단한다. 실패·시간 중단도 당일에 자동 재시도하지 않고 다음 날짜에 남은 커서를 재개한다. 따라서 하루에 전체 자료를 전부 갱신한다고 보장하지 않는다. 제공기관을 호출하기 전에 DB에서 중복을 확인하므로 중복 요청도 DB 읽기·함수 실행 비용은 발생할 수 있다.

한 실행의 엔진 시간 예산은 40초, lease는 120초, 경로의 배포 실행시간 설정은 60초다. 제공기관의 단일 요청은 15초 제한, redirect 거절, 최대 응답 2 MB 제한을 사용한다. 수량은 페이지와 항목 중 먼저 도달하는 제한을 따른다. 숨은 재시도·자가 호출·유료 대체 공급자는 없다.

## 저장, 재개, 검수 데이터 보존

기본 작업 ID는 `visitjeju-ko`이고 원본 언어는 한국어다. `syncJobs/{jobId}`가 진행 커서와 lease를, 하위 `runs/{runId}`가 시작·종료·처리량·오류 이력을 저장한다. 항목의 저장과 다음 커서는 같은 트랜잭션으로 기록한다. lease 소유자·fence·만료시각을 확인해 오래된 실행이 진행 상태를 덮어쓰지 못하게 한다.

원본 페이지 내용이 달라지면 해당 페이지의 offset을 처음부터 확인한다. 커서에 페이지별 처리 ID(`seenKeys`, 최대 2,000개)를 보관하여 이미 처리한 항목은 로컬에서 건너뛴다. 앞부분 자료가 매일 바뀌어도 뒷부분을 영구히 놓치지 않도록 하며, 기처리 ID의 변경은 다음 전체 주기에서 hash로 확인한다. 제한에 도달하면 `paused`, 전체 조회를 마치면 커서를 첫 페이지로 되돌린다. 중간 오류 전에 성공한 항목은 남기며, 생성·수정이 있었다면 공개 카탈로그 캐시를 만료시킨다.

공식 분류값·부모 지역·라벨이 확인된 항목만 처리한다. 알 수 없는 분류나 충돌은 거절 건수와 제한된 오류 샘플로 남기고, 임의 분류로 공개하지 않는다. 사진 URL은 후보로만 보관한다. 장소 사진을 내려받거나 이미지 사용권을 자동 승인하지 않는다.

`sourcePlaces/{contentId}`에는 기본 출처 정보와 정규화 결과를, `places`에는 운영자 편집 정보를 둔다. 신규 운영 문서는 `draft`로 생성된다. 이후 수집은 기본 원문을 갱신하고, 기존 검수된 동행 정책·요금·사진 권리·게시 상태를 덮어쓰지 않는다. 이미 게시된 문서의 주소·권역·유형·좌표가 달라진 경우에는 기존 공개 값을 유지하고 새 원문 및 `editorialReviewRequired`/`changedEditorialFields`에 재검토 필요를 남긴다. 새 주소에 과거 시설·사진 검증을 그대로 붙이지 않기 위한 분리다. 원본에서 사라진 항목을 한 번의 누락만으로 삭제하지 않는다. 자동 보존기간 만료·이력 삭제 작업은 구현하지 않았으므로 저장량은 운영 검토 대상이다.

## 공개 카탈로그 읽기

`DEMO_MODE=true`는 명시적인 가상 예제 모드다. 기본 `CLOUD_SERVICES_ENABLED=false`에서는 로컬 관측 카탈로그를 사용한다. 클라우드가 승인되어 켜진 경우 `readFirestoreSyncCatalog()`가 수집 기본 정보와 운영자 문서를 합친다. 로컬 목록과 자동 합산하지 않는다.

수집 기본 정보는 동행 조건 전부 `unknown`, 요금·소요시간 `null`, 사진 placeholder로 공개한다. 이 단계는 현장 검수가 끝났다는 의미가 아니다. 같은 출처의 운영자 `published` 문서는 검수값으로 우선하며 `hidden`, `suspended`, `closed` 상태는 수집 기본 정보도 가린다. 원본 객체, 후보 사진, 내부 메모는 공개하지 않고 공개 타입으로 재검증한다.

읽기 캐시는 60초이며 수집의 생성·수정 또는 운영자 변경 후 만료된다. 컬렉션은 500개씩 페이지로 읽으며 컬렉션당 10,000개를 넘으면 오류를 반환한다. 읽기 오류를 로컬·데모 데이터로 조용히 바꾸지 않는다. 수집을 중단해도 클라우드 읽기가 허용된 동안 마지막 저장 데이터는 읽을 수 있다. 자료 신선도·휴폐업 상태는 별도 확인이 필요하다.

### 공개 조회 비용은 수집 한도와 별개

현재 `getAdminServices()`의 공개 읽기 게이트는 `CLOUD_SERVICES_ENABLED`다. `VISITJEJU_SYNC_ENABLED=false`나 동기화 승인 만료는 원문 수집·저장을 막지만 **공개 카탈로그 조회까지 차단하지 않는다.** 클라우드를 켜면 예약 작업이 하나도 없어도 페이지 방문·빌드·캐시 채움에서 Firestore 읽기가 발생할 수 있다. 공개 읽기·호스팅·트래픽 비용의 승인과 중단 방법을 별도로 확정하지 않았다면 `CLOUD_SERVICES_ENABLED=false`를 유지한다.

한 번의 캐시 채움은 두 컬렉션 전체를 읽으므로 정상 범위에서 최대 20,000개 문서를 반환받을 수 있다. 각 컬렉션의 10,000개 상한은 비용 한도가 아니다. 초과를 확인하는 마지막 500개 묶음도 먼저 읽고 오류를 내므로, 상한 초과 시 추가 읽기가 발생할 수 있다. 60초 재검증은 고정 타이머가 아니라 요청에 따라 이루어지지만 방문이 계속되면 자주 재검증할 수 있고, 배포·태그 만료·캐시 분산으로 채움 횟수가 늘어날 수도 있다.

규모를 이해하기 위한 단순 예로, 캐시 채움마다 20,000개 문서를 읽고 분당 한 번씩 하루 동안 반복하면 문서 반환 건수는 28,800,000건이다. 이는 실제 비용 견적이나 보장된 상한이 아니다. 제공기관 API의 2페이지/100항목 실행 제한도 이 공개 읽기량을 제한하지 않는다. 운영 전 실제 플랜·잔여 무료량·과금 단위·배포 캐시 동작을 확인하고, 큰 자료에서는 서버 조회 조건·페이지 API·사전 계산된 공개 스냅샷 등 읽기 구조를 조정한 뒤 별도 승인 범위를 확정해야 한다. 현재 실제 클라우드 호출은 하지 않았다.

### 로컬 검수 사실의 이전

기존 60곳의 로컬 `applyCatalogFacts`에 반영된 어린이·반려견 조건은 `sourcePlaces`나 `places`에 자동 업로드되지 않는다. 클라우드 읽기 어댑터도 로컬 자료를 몰래 합치지 않는다. 이전 없이 클라우드를 켜면 해당 검수 결과가 클라우드 화면에서 미확인으로 보일 수 있다. 원문 수집 성공과 검수 정보 이전 완료를 구분해야 한다.

운영 전환 시 콘텐츠 ID를 맞추고, 확인된 항목·원문·확인일·수동 예외를 검토한 뒤 승인된 DB 쓰기 범위에서 명시적으로 이전한다. 현재 게시 검증은 필수 사실 확인을 요구하므로 부분 검수 overlay의 게시 정책도 별도로 검토해야 한다. 테스트나 수집 시작만으로 기존 검수 내용이 이전됐다고 기록하지 않는다.

## 장애 확인과 중단

`VISITJEJU_SYNC_ENABLED=false`로 새 수집을 차단하고 활성 예약도 별도로 제거한다. 승인 만료 뒤에는 제공기관 호출과 저장 단계에서도 준비 조건을 다시 검사한다. 중단된 작업의 lease는 만료 후 새 실행이 인계한다. 임의로 run 문서를 지워 당일 제한을 우회하지 않는다.

`readFirestoreSyncStatus()`는 마지막 상태와 최근 실행 이력을 읽는 서버 함수다. 공개 HTTP 상태 경로는 없다. 별도 관리자 경로를 추가할 때는 검증된 관리자 인증과 클라우드 비용 승인이 필요하다. 테스트 중 실제 DB 상태를 조회하지 않았다.

API 키 변경, endpoint·파라미터 변경, 수집 범위 확장, 저장·재공개 조건 변경은 기존 승인 범위와 제공기관 계약을 다시 확인한다. 원본 정책과 최신 비용 조건 확인은 [제공기관 조사 기록](../research_notes/sources/provider-access-2026-11-08.md)을 시작점으로 한다.

## 로컬 검증

모든 테스트는 메모리 저장소 또는 모의 어댑터를 사용한다. 실제 제공기관 호출·Firestore·배포를 검증한 결과로 해석하지 않는다.

```sh
npm run test -- src/lib/sync src/app/api/cron/visitjeju/route.test.ts src/lib/server/public-places.test.ts
npm run typecheck
```

인증 실패·설정 누락·승인 만료·실행 한도·일일 run ID·오류 비밀값 제거·HEAD 비실행을 검사한다. 엔진에서는 중복·lease·커서 재개·부분 실패·검수값 보존을, 공개 읽기에서는 게이트·안전한 변환·오류·캐시 무효화를 검사한다. `.env.local`과 실키는 테스트 fixture나 배포 예시에 넣지 않는다.
