# 10. 로드맵과 협업

## 단계

기간은 주간 작업 시간이 정해지지 않은 상태의 제안값이다. 팀 일정에 맞춰 조정한다.

| 단계 | 기간 | 산출물 | 완료 조건 |
|---|---|---|---|
| 0. 준비 | 1주 | 프로젝트 초기화, Firebase, Vercel, 카카오 키 | 미리보기 배포 성공 |
| 1. 기반 | 1~2주 | 디자인 토큰, 언어, 테마, 샘플 데이터, 판정 로직 | 판정 테스트 통과 |
| 2. 핵심 흐름 | 2주 | 홈, 지역·유형, 결과, 상세 | 샘플로 전 흐름 동작 |
| 3. 계정·저장 | 1주 | 구글 로그인, 저장, 공유 | 인앱 브라우저 시나리오 통과 |
| 4. 관리자 | 2주 | 입력, 검수, 재확인, 신고 | 운영진이 장소 게시 가능 |
| 5. 데이터 | 3~4주, 병행 | 200곳 확인, 번역, 사진 | 게시 조건과 권역 할당 충족 |
| 6. 비공개 베타 | 2주 | 지인 20~30팀 테스트 | 치명 오류 없음 |
| 7. 공개 베타 | 8주 | 공개, 측정, 운영 | 아래 평가 기준 판단 |

## 첫 구현 순서

1. Next.js 프로젝트와 도구 설정
2. `docs/06`의 토큰과 기본 컴포넌트
3. `src/lib/verdict`와 테스트
4. 샘플 장소 12곳
5. 홈 → 지역·유형 → 결과 → 상세
6. 다크 모드, 다국어
7. 인증과 저장
8. 지도와 외부 길찾기
9. 관리자
10. 실데이터 투입

## 팀 분담 제안

회의에서 합의한 '각자 맡은 영역을 합치는 방식'을 살린다. 담당자는 다음 모임에서 확정한다.

| 역할 | 담당 영역 | 산출물 |
|---|---|---|
| 아이 담당 | 아이 조건 항목, 맘카페 조사, 아이 데이터 검수 | 키즈 프렌들리 정의, 조건별 사실 문구 |
| 반려견 담당 | 반려견 조건 항목, 법규 추적, 숙소 조건 | 동반 조건표, 제도 변경 메모 |
| 실버 담당 | 어르신·접근성 항목, 부모 동반 조사 | 물리 조건표, 어르신 사용성 테스트 |

각 담당은 권역 하나씩을 맡고 나머지 권역은 함께 처리한다. 개발은 AI 도구로 나누어 진행하며, 공통 규칙은 `CLAUDE.md`로 고정한다.

## 공동 작업 규칙

- 저장소를 하나만 쓰고 기능별 브랜치와 PR로 합친다.
- 판정 규칙이나 조건 항목을 바꾸면 `docs/07`을 먼저 갱신한다.
- 근거 없이 큰 방향을 바꾸지 않는다. 주장에는 데이터나 사용자 사례를 붙인다.
- 비판 라운드: 새 기능은 '안 되는 이유'를 한 번 듣고 AI로 근거를 확인한다.
- 회의 결과는 `docs/01`에 이어서 기록한다.

## 테스트

| 종류 | 도구 | 대상 |
|---|---|---|
| 단위 | Vitest | 판정, 신선도, 필터, 길찾기 링크 |
| 보안 규칙 | Firebase Emulator | 사용자별 저장 접근, 공개 쓰기 차단 |
| E2E | Playwright | 복수 동행 검색, 로그인 복귀 저장, 관리자 게시 |
| 번역 | 스크립트 | 메시지 키 누락 |
| 접근성 | axe, 수동 | 주요 화면 |
| 실기기 | 수동 | iOS Safari, Android Chrome, 카카오톡 인앱 |

필수 판정 테스트:

- 세 동행 모두 맞음 → 맞음
- 하나 조건부 → 조건부
- 하나 미확인, 나머지 맞음 → 미확인
- 하나 맞지 않음 → 맞지 않음
- 반려견 크기 선택 없음과 초과
- 어르신 좌식 전용 → 맞지 않음
- 정책 항목 장기 미확인 → 미확인

## 베타 평가 기준

통과 기준은 벤치마크가 아닌 잠정값이다.

| 질문 | 지표 | 잠정 기준 |
|---|---|---|
| 정보가 현장에서 맞나 | 방문 응답자의 핵심 조건 불일치 | 5% 이하 |
| 쓸 가치가 있나 | 결과 조회 뒤 전화·길찾기·저장 행동 | 40% 이상 |
| 공유되나 | 공유 사용자 비율 | 15% 이상 |
| 로그인 장벽 | 저장 시도 뒤 저장 완료 | 60% 이상 |
| 데이터 유지가 가능한가 | 재확인 기한 준수 | 90% 이상 |
| 복합 일행이 있나 | 동행 2개 이상 검색 비중 | 측정 후 판단 |
| 숙소가 필요한가 | 숙소 포함 검색과 행동 | 측정 후 축소 판단 |
| 외국어가 필요한가 | 언어별 사용자와 행동 | 측정 후 축소 판단 |

## 주요 위험

| 위험 | 대응 |
|---|---|
| 데이터 갱신 부담이 큼 | 초기 20곳으로 시간 측정, 필요 시 숙소·언어 축소 |
| 업주가 공개를 거부 | 후보를 넉넉히 확보, 무리하게 공개하지 않음 |
| 구글 로그인으로 저장 이탈 | 지표 측정, 인앱 안내, 필요 시 대안 검토 |
| 번역 오류로 현장 혼란 | 사실은 enum으로, 자유 텍스트 최소화, 자동 번역 표시 |
| 키즈와 반려견 충돌 | 사실 표시, 구역 분리, 필터 제공 |
| 맛이 없어 재사용 안 함 | 평판 확인 후 후보 선정 |
| 네이버가 조건 자동 요약 제공 | 확인일과 복합 판정으로 차별화 |
| 공공기관이 표준 데이터 공개 | 조사 원가 절감 기회로 활용 |
