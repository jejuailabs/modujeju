# 제주 동행 맞춤 여행 앱 사전 브리핑

작성일: 2026년 11월 7일
작업 저장소: modujeju / 기존 기획명: 같이제주
상태: 폴더 분석, 이미지 자산 제작, 공식 데이터 조사, Firebase 로컬 설정, GitHub 초기화 완료. 실행 앱 구현 전 단계.

같이제주는 아이, 반려견, 어르신이 함께하는 일행에게 **모두 이용할 수 있는 제주 장소와 그 이유를 보여주는 여행 앱**으로 설계한다. 감성적인 제주 이미지로 여행의 기대를 만들고, 선택 이후에는 동행 조건·가격·이동 부담을 명확하게 보여주는 것이 핵심이다.

작업 시작 시 Markdown 17개와 합성 시안 PNG 1개가 있었다. 앱 소스, package.json, 실행 환경, 실제 장소 데이터셋은 없었다. reg/design_ref.png는 이번 첨부 이미지와 동일하다.

- reports 및 research_notes: 시장 조사와 타깃별 불편 사항.
- CLAUDE.md: 기존 제품 원칙과 기술 계획.
- 누락: 문서들이 참조하는 docs/06_design_system.md와 분리된 디자인 자산.

기존 기술 계획은 Next.js·TypeScript·Tailwind, Firebase, Vercel, 카카오맵이다. 현재 구현된 스택으로 오해하면 안 된다. 배포·데이터베이스 생성·유료 API 활성화는 이번에 실행하지 않았다.

## 이번 요청에 따른 제품 확장안

| 구분 | 기존 문서 | 이번 방향 |
|---|---|---|
| 장소 | 식당·카페·숙소 200곳 계획 | 관광·체험·산책을 포함한 여행 스팟 |
| 데이터 | 운영진 직접 입력, 공공자료는 후보 발굴 | 비짓제주 기본정보 수집과 동행 조건 보강 |
| 가격 | low/mid/high 저장 필드 | 금액·단위·추가 요금·확인일과 필터 |
| 추천 | 맞춤 장소·저장 | 장소 탐색을 중심으로 지도·일정·여행 중 대안 연결 |
| 일정 | 시간표형 일정과 AI 코스 제외 | 저장 장소를 기반으로 선택적으로 일정 구성 |

위 확장안은 이번 브리핑의 제안이며 기존 문서 전체를 덮어쓴 결정이 아니다. 기존의 복수 동행, 항목별 사실과 확인일, 미확인 상태, 운영자 검수 구조는 재사용한다.

## 여행자의 생각을 따라가는 화면

1. **여행을 기대한다.** 제주 바다와 일행의 모습을 담은 히어로. 문구는 “함께 가는 모두에게, 편안한 제주”. 첫 버튼은 “우리 일행 맞춤 장소 찾기”.
2. **누구와 가는지 정한다.** 아이·반려견·어르신 복수 선택. 아이 나이와 유모차, 반려견 체중과 실내 필요, 계단 회피와 짧은 보행 등은 필요한 경우만 펼친다.
3. **지금 필요한 범위를 좁힌다.** 동·서·남·북 및 전체/아직 미정, 식당·카페·숙소·관광·체험·산책, 유형별 예산을 선택한다. 날짜·숙소 위치는 일정 구성 시 보강한다.
4. **갈 수 있는 이유를 비교한다.** 목록과 지도를 오가며 적합 이유, 제한, 금액 기준, 확인일을 본다. 결과가 없으면 지역·가격 범위 확대를 제안하며 동행의 필수 조건은 임의로 풀지 않는다.
5. **마음에 드는 곳을 저장한다.** 상세에서 항목별 근거를 확인하고 전화·길찾기·저장·공유로 이어간다.
6. **필요하면 하루를 구성한다.** 저장 장소를 날짜별로 묶고 이동·체류·휴식을 고려한다. 실제 이동시간 계산이 없는 상태에서는 확정 시간표처럼 표시하지 않는다.
7. **여행 중 변화를 처리한다.** 비가 오거나 휴무·입장 조건이 바뀌면 같은 지역의 조건 맞는 대안을 찾는다. 확인되지 않은 실시간 날씨·혼잡도·영업 상태는 확정 정보처럼 쓰지 않는다.

첫 결과까지는 동행과 지역·유형을 고르는 짧은 흐름을 유지한다. 일정부터 강요하지 않고 장소 탐색의 가치를 먼저 체험하게 한다.

## 복합 동행의 판단 기준

여러 동행의 필수 조건을 모두 만족하는 장소를 우선한다. 한 명의 입장 불가를 다른 항목의 높은 점수로 상쇄하지 않는다. 어르신이라는 이유만으로 계단이나 좌식 이용을 일괄 금지하지 않고, 사용자가 선택한 실제 필요를 적용한다.

| 상태 | 의미 | 화면 표현 예 |
|---|---|---|
| 가능 | 선택한 필수 조건이 확인됨 | 유모차 진입·반려견 실내·입식 좌석 확인 |
| 조건부 | 제한을 확인하고 선택해야 함 | 반려견은 테라스만 이용 |
| 미확인 | 판단에 필요한 근거가 부족함 | 출입구 단차 아직 미확인 |
| 부적합 | 선택한 필수 조건과 충돌함 | 반려견 동반 불가 |

가상 예: 4세 아이, 8kg 반려견, 계단을 피하고 싶은 부모님이 동부에서 식당을 찾는다. 유아 의자·반려견 허용 체중·무단차 출입이 확인된 곳을 우선하고, 야외 좌석만 가능한 곳은 조건부로 표시한다. “8kg 미만”과 “8kg 이하”를 구분한다.

장소 카드에는 사진과 이름 다음으로 “왜 우리 일행에게 맞는지”를 보여준다. 구체적 제한은 칩이나 작은 글씨 속에 숨기지 않는다.

## 가격과 지역 기준

식당은 1인 식사비, 카페는 1인 주문비, 숙소는 날짜·인원 기준 객실 1박, 체험은 성인·어린이 1인 요금으로 비교한다. 반려견 추가 요금, 주차비, 성수기 변동을 별도 항목으로 둔다. 가격 미확인을 무료로 취급하지 않는다.

권역은 화면용 구분과 행정구역을 매핑해 관리한다. 첨부 시안은 동부를 선택한 뒤 서부의 협재·한림을 일정에 포함한다. 실제 추천에서는 선택 지역과 이동 범위가 일치하도록 검증해야 한다.

## 공식 데이터 조사 결과

[비짓제주 API 안내](https://www.visitjeju.net/kr/visitjejuapi)는 사용기관명·이메일 인증·이용목적을 받아 담당자 승인 후 키를 발급한다. 과다 트래픽에 따른 제한이 있으며 공개 안내만으로 과금·초과사용 조건은 확정하지 못했다. API 신청이나 데이터 호출은 실행하지 않았다.

공식 [활용 가이드 PDF](../research_notes/sources/visitjeju-open-api-guide.pdf) V1.1, 2026년 6월판은 콘텐츠 ID, 유형, 지역, 주소, 좌표, 연락처, 소개, 태그, 대표사진 경로 등을 문서화한다. 가격·체중 제한·무단차 출입·항목별 확인일은 전용 응답 필드로 명시되어 있지 않다. 웹 상세에 표시되는 정보가 API에도 모두 제공된다고 가정하면 안 된다.

[혼저옵서개](https://www.visitjeju.net/kr/trend/jejupets?menuId=DOM_200000000010960&cate1cd=cate0000000002)와 [무장애 시설 제공 관광지](https://www.visitjeju.net/kr/tourInfo/able?tap=two&menuId=DOM_000002000000000081)는 후보를 찾는 출처다. 실제 열람한 카멜리아힐 상세에는 요금, 계절별 영업시간, 반려견 체중, 경사도, 일부 접근성 시설이 있었다. 목록 포함 여부만으로 모든 동행의 이용 가능을 확정하지 않는다. 웹 조회일과 업소가 정책을 확인한 날짜도 구분한다.

[제주관광 빅데이터 플랫폼](https://data.ijto.or.kr/bigdata/sub05_01.do)은 소비·이동·방문 통계와 보고서를 제공한다. 지역·계절별 수요 판단을 보조할 수 있지만 개별 장소의 입장 조건이나 현재 가격을 대신하지 않는다.

[포토제주 이용 조건](https://www.visitjeju.net/photojeju/ccl)은 사진별 라이선스 확인을 요구하는 구조다. 상업 이용·수정 가능 여부와 출처 표시를 각각 기록한다. 포토제주 조건을 모든 비짓제주 API 사진에 일괄 적용하지 않는다.

추천 데이터 흐름은 허용된 출처 수집 → ID·지역·유형 정규화 → 동행 조건과 가격 보강 → 출처·확인일 기록 → 필수 조건 판정 → 취향과 동선에 따른 정렬이다. 초기 구현은 규칙 기반으로 설명 가능하게 만들 수 있으며, 유료 AI 호출은 필수 전제가 아니다.

## 디자인과 생성 자산

따뜻한 크림 배경, 코럴 강조색, 진한 갈색 본문, 바다와 유채꽃 이미지를 사용한다. 홈에는 감성 이미지를 크게 쓰고, 결과·상세에서는 조건과 가격의 가독성을 우선한다. 본문과 조작 요소는 최소 16px, 터치 영역은 최소 48px을 기준으로 한다.

내장 image_gen으로 PNG 15종을 생성했다.

| 자산 | 수량 | 용도 |
|---|---:|---|
| 가족·아이·반려견·어르신 히어로 | 1 | 홈 |
| 아이·반려견·어르신 아바타 | 3 | 동행 선택 |
| 동·서·남·북 권역 풍경 | 4 | 지역 선택 |
| 가상 아쿠아리움·감귤 농장·해변 카페 | 3 | 시안용 장소 카드 |
| 감귤·돌하르방·유채꽃 투명 장식 | 3 | 브랜드 장식 |
| 제주 해안 파노라마 | 1 | 헤더와 소개 |

별도로 로고 마크와 UI용 원본 SVG 12종을 만들었다. 파일 읽기, 해상도, 필요한 알파 투명도, SVG XML 검증을 통과했다. PNG는 원본 자산이며 앱 적용 시 표시 크기에 맞춘 최적화가 필요하다.

생성한 가상 장소 사진은 실제 업체명과 연결하지 않는다. 운영용 장소 사진은 사용 근거를 확인한 실제 사진으로 연결한다. 글자와 버튼은 이미지에 합치지 않고 UI에서 렌더링한다.

## 설정과 저장소 상태

Firebase 웹 설정과 서버 전용 서비스 계정 필드를 .env.local에 저장했다. 프로젝트 일치와 개인키 줄바꿈 복원 검증을 통과했다. 이 파일은 Git에서 제외하며 비밀값 없는 .env.example만 공유한다. Firebase 리소스 생성, SDK 연결 시험, Analytics 초기화는 이번 범위에 포함하지 않았다.

요청한 [jejuailabs/modujeju](https://github.com/jejuailabs/modujeju) 저장소에 main 브랜치 초기 커밋 146034a를 push했다. 원격 초기 커밋에는 README.md, .gitignore, .env.example 세 파일만 포함된다. 기획·조사·생성 이미지 산출물은 현재 로컬 작업 폴더에 있다.

## 구현 순서 제안

1. 누락된 디자인 시스템과 이번 확장 범위를 정리한다.
2. 생성 자산과 명시적인 가상 데이터를 사용해 동행 선택·필터·결과·상세·저장 흐름을 로컬에서 구현한다.
3. 공식 API의 이용·비용 조건, 신청자 정보, 키 발급을 확정하고 데이터 어댑터와 검증 대기열을 연결한다.
4. 실제 확인된 장소 데이터로 복합 동행 추천을 검증한다.
5. 날짜·숙소·이동시간·휴식·휴무를 반영할 수 있을 때 일정 기능을 연결한다.
6. Firebase·지도·호스팅의 구체적 요금·무료 한도·초과 조건을 확인하고 추가 과금이 있는 범위만 별도 승인 후 활성화한다.
