# 02. 제품 정의

## 한 문장

**같이제주는 아이, 반려견, 어르신과 함께하는 일행이 모두 편한 제주의 식당·카페·숙소를, 언제 확인했는지까지 보여주는 모바일 웹앱이다.**

슬로건: 함께 가는 제주여행, 모두가 편해야 진짜 여행이니까

## 해결할 문제

주 사용자는 일행의 여행을 짜는 사람이다. 이들은 지금 전화, 블로그, 지도 앱을 오가며 다음 질문의 답을 찾는다.

> 우리 일행이 이곳에 들어가서 편하게 머물 수 있나? 그 정보를 믿어도 되나?

| 동행 | 대표 문제 |
|---|---|
| 아이 | 노키즈존을 도착해서 안다. 유아 의자, 맵지 않은 메뉴, 유모차 진입 여부를 미리 알기 어렵다. |
| 반려견 | 동반 가능 표시가 있어도 실내 가능 여부, 크기 제한, 준비물이 불분명하다. |
| 어르신 | 입식 좌석, 계단, 주차 거리 같은 물리 정보가 방문 전에 없다. |

## 시안에서 읽은 핵심 가치

| 시안 요소 | 읽어낸 가치 | 제품 원칙 |
|---|---|---|
| 슬로건 "모두가 편해야" | 한 사람이 아닌 일행 전체 | 판정은 가장 불편한 사람 기준 |
| 첫 화면의 세 동행 버튼 | 맛집이 아니라 '누구와'로 시작 | 첫 입력은 동행 |
| 동행 → 지역 → 장소 3단계 | 고민 없는 단순함 | 세 번 안에 결과 |
| 유아 의자, 유모차 진입, 맵지 않은 디저트 태그 | 평점보다 구체적 사실 | 사실 태그 중심 카드 |
| 돌하르방, 유채꽃, 감귤, 둥근 카드 | 제주의 따뜻한 환대 | 공공 앱이 아닌 친근한 톤 |
| 일정 저장, 길찾기 | 정보에서 행동으로 | 찾으면 바로 저장하고 이동 |

## 시안에서 바꾸거나 더하는 것

| 항목 | 시안 | 구현 |
|---|---|---|
| 동행 선택 | 버튼을 누르면 이동 | 켜고 끄는 복수 선택 후 '다음' |
| 신뢰 정보 | 없음 | 카드와 상세에 확인 날짜, 상세에 근거 유형 |
| 판정 | 태그만 있음 | 맞음, 조건부, 맞지 않음, 미확인 |
| 결과 제목 | 추천 일정 | 맞춤 장소. 시간표를 제공하지 않으므로 이름을 바꾼다 |
| 결과 하단 | 일정 저장, 길찾기 | 전체 저장, 지도로 보기. 길찾기는 장소가 정해지는 상세 화면에 둔다 |
| 알림 벨 | 있음 | 베타에는 알림이 없어 언어 선택으로 대체 |
| 실물 사진 | 일러스트 | 실제 업소는 허락된 실제 사진만 사용 |
| 추가 화면 | 없음 | 장소 상세, 저장 목록, 로그인, 관리자 |
| 추가 설정 | 없음 | 다크 모드, 4개 언어 |

## 타깃

- **주 사용자:** 동행의 식사와 숙소를 정하는 여행 기획자
- **함께 쓰는 사람:** 기획자가 보낸 링크를 받아 보는 부모님과 일행
- **외국어 사용자:** 영어, 중국어, 일본어 사용 여행자. 수요는 미검증이므로 베타에서 측정한다

## 범위

### 포함

- 제주 4권역, 총 200곳: 권역별 식당 25, 카페 15, 숙소 10곳
- 동행 복수 선택, 지역·유형 선택, 조건 기반 결과
- 장소 상세, 근거 표시, 지도, 외부 앱 길찾기
- 구글 로그인 사용자의 저장 목록
- 링크 공유, 오류 신고
- 라이트·다크 모드, 한국어·영어·중국어·일본어
- 운영진 전용 관리자 화면

### 제외

- 자체 별점, 자유 리뷰, 커뮤니티
- 예약, 결제
- 시간표형 일정 생성, AI 코스 추천
- 사장 계정과 직접 입력
- 푸시 알림
- 광고 집행 기능

## 비즈니스 원칙

- 업소 등록은 무료다. 운영진이 확인해 입력한다.
- 유료 광고를 도입해도 '광고'로 표시하고 조건 정보 영역과 분리한다.
- 광고주가 판정, 정렬, 확인 표시를 바꿀 수 없다.
- 후보 수익원은 숙소·렌터카 제휴, 데이터 공급, 표시된 광고다. 어떤 수익원도 아직 입증되지 않았으므로 베타에서는 구현하지 않는다.

## 결정 기록

| 결정 | 선택 | 이유와 감수할 점 |
|---|---|---|
| 범위 | 식당·카페·숙소 동일 깊이 | 시안과 회의의 여행 전반 의견을 반영. 조사량이 늘어 리포트 권고보다 넓다 |
| 동행 | 복수 선택 | 복합 일행을 처리하고 차별점을 살림. 세부 프로필은 결과 필터로 대체 |
| 결과 | 조건 맞는 장소 + 저장 | 시간표 구현 대신 데이터 정확성에 집중 |
| 1차 목표 | 공개 베타 | 실제 사용자 검증. 데이터 운영이 일정의 핵심 위험 |
| 스택 | Next.js, Firebase, Vercel | 제품 책임자 지정 |
| 저장 | 구글 로그인 사용자만 | 기기 간 동기화가 쉽다. 저장 시 이탈 가능성을 측정한다 |
| 지도 | 카카오맵 표시, 외부 앱 길찾기 | 지도 구현 부담을 줄임. 외국어 사용자는 구글 지도 링크를 우선 제공 |
| 데이터 범위 | 4권역 200곳 | 시안 유지와 운영 가능 규모의 절충 |
| 언어 | 한·영·중·일 | 처음부터 4개. 번역 품질 관리가 필요하다 |
| 데이터 입력 | 운영진 직접 입력만 | 품질 통제가 쉽다. 갱신 부담은 모두 운영진이 진다 |
| 위생 충돌 | 사실 표시와 '반려동물 없는 곳' 필터 | 어느 쪽도 배제하지 않고 선택권을 준다 |

## 리포트와 다른 선택

시장분석 리포트는 식당·카페 집중, 외국어 제외, 두 권역을 권했다. 현재 계획은 숙소를 포함하고, 4개 언어와 4권역으로 넓혔다. 시안과 회의 의견을 우선한 제품 결정이며, 데이터 운영 부담이 커진다. 베타 결과에서 저사용 범위는 축소를 검토한다.
