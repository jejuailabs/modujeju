# 공식 자료 수집·갱신 절차

작성일: 2026-11-08

## 현재 자료의 성격

현재 기본 카탈로그 66곳은 비짓제주의 공개 목록·상세 페이지를 컴퓨터 유즈로 열람하여 기록한 시작 스냅샷이다. 식당·카페·숙소 각 20곳에 관광지 6곳을 추가했다. 데이터 상한이나 최종 수집 범위는 아니다. 실제 장소의 기본 정보와 출처가 있지만 모든 이용 조건을 현장·전화로 검증한 자료는 아니다. 공개 페이지의 관측과 API 이용 승인은 별개의 절차다. 이후 자료를 계속 공급할 동기화 코드와 cron 진입점은 준비되어 있으나 실제 API 호출·예약 배포는 승인 전 꺼져 있다.

`research_notes/catalog/restaurants.json`, `cafes.json`, `stays.json`, `attractions.json`을 수집 원본으로 보관한다. `src/data/catalog.ts`가 배열을 통합하고 `src/lib/official-catalog.ts`가 공개 `Place`로 변환한다. 원본은 비밀키나 서비스 계정 파일을 포함하지 않는다. [구현·검증 기록](12_delivery_check.md)의 60곳 검증은 관광지 추가 이전 기록이다.

관광지 6곳은 카멜리아힐·비자림·천지연폭포·협재해수욕장·오설록 티 뮤지엄·성산일출봉이다. 공개 페이지 열람일은 2026-11-08이며, 시설 정책의 갱신일은 확인되지 않았다. 반려동물 체급·입욕 제한, 코스별 경사와 계단, 화장실 유효공간 등은 출처 관측으로 보존하되 시설 판정은 모두 `unknown`이다. 관광지 통합·분류 변경 관련 5개 파일의 로컬 테스트 66개를 통과했으며 외부 API나 DB를 호출하지 않았다.

## 재수집 순서

1. 대상 유형·권역·장소와 변경 이유를 정한다. 기존 `sourceId`·`sourceUrl`로 같은 장소인지 확인하고 상호가 비슷한 다른 지점을 합치지 않는다.
2. 비짓제주 공개 상세 페이지를 직접 연다. 이름, 실제 주소, 본문·시설·입장 제한 영역을 확인한다. 목록 카드의 광고, 검색 결과 요약, 후기와 공식 상세 표시를 구분한다.
3. 원문 표기, 상세 URL, 실제 열람 시각을 JSON에 기록한다. 페이지에 없거나 의미가 불명확한 값은 비워 두거나 `null`로 보존한다. 날짜를 오늘로 바꾸는 것만으로 기존 내용을 재검증한 것으로 처리하지 않는다.
4. 태그와 관측 문장을 별도 필드에 기록한다. 동행 정책을 판정 항목으로 반영하려면 대상, 실내/실외, 나이·체중 경계, 캐리어, 적용 공간·기간을 별도로 검토한다.
5. 기존 자료와 차이를 검토한다. 상호 변경·주소 변경·휴폐업·정책 변경은 기존 ID를 기준으로 처리하고, 새 장소로 복제하여 과거 자료를 계속 노출하지 않는다.
6. 통합 배열의 유형·권역·중복·출처와 `mapOfficialCatalog` 검증을 확인한다. 단위 테스트·타입 검사·린트·로컬 빌드 후 카드, 상세, 필터, 저장·일정의 실제 동작을 검수한다.
7. 기록에 변경자·검수자·변경일·근거를 남기고 배포 책임자가 반영한다. 이 저장소를 수정했다고 운영 사이트가 자동으로 갱신됐다고 기록하지 않는다. 유료 서비스 이용이나 비용이 불확실한 배포는 사용자 비용 승인 범위 안에서만 진행한다.

## 입력 필드

| 필드 | 기록 기준 |
|---|---|
| `name`, `address` | 실제 상세의 상호·주소. 문자열 또는 검토된 4언어 객체. 임의 번역·지점명 추가 금지 |
| `region`, `type` | 내부 탐색용 권역·유형. 수집자가 주소와 시설 성격을 검토하여 지정 |
| `district`, `summary` | 확인한 행정구역·간단한 사실 요약. 원문 장문 복사나 광고 최상급 표현을 피함 |
| `sourceUrl`, `sourceId` | HTTPS 상세 URL·공급자의 콘텐츠 ID. 동일 장소 추적과 중복 방지에 사용 |
| `sourceTags` | 원문에 실제 표시된 태그. 검색과 원문 분류 설명용 |
| `tags` | 별도로 검토한 내부 검색어. 입장 정책 확인을 대신하지 않음 |
| `observations` | `{field, value, sourceUrl, verifiedAt?}` 형태의 관측. `verifiedAt: null`은 시설·정책 근거일 미확인으로, 기본 열람일을 대신 사용하지 않는다. 새 관광지 관측에는 이 값을 명시한다. 날짜가 있는 관측은 2025년 이후의 유효한 근거일과 신선도를 확인한 뒤 시설 표시에 사용한다. 짧은 `quote` 등 추가 검수 기록은 원본에 남길 수 있음 |
| `retrievedAt` | 실제 열람 시각(ISO timestamp 권장) 또는 실제 열람일. 원본 갱신일과 다름 |
| `basicSourceCheckedAt` | 기본 정보 열람일. 미지정 시 열람 기록에서 산출. 정책·시설의 `verifiedAt`와 구분 |
| `lat`, `lng` | 확인한 좌표만 숫자로 기록. 한 쌍을 확인하지 못하면 공개 좌표는 둘 다 `null` |
| `durationMinutes` | 근거가 있는 소요시간만 기록. 알 수 없으면 `null`이며 0분으로 대체하지 않음 |

현재 `Place`의 기본 요금과 반려견 추가요금은 확인 전 `null`, 동행 판정 사실은 `unknown`으로 시작한다. 원문 관측 문장 자체를 기계적으로 모두 검증 사실로 승격하지 않는다. `sourceObservations`는 출처 표시용이며, 판정에 사용하는 `facts`는 검수된 범위만 반영한다.

`src/data/catalog-facts.ts`의 수동 검수 목록은 콘텐츠 ID, 출처 URL, 관찰 항목, 검토한 문구가 모두 일치할 때만 개별 사실을 반영한다. `verifiedAt`는 해당 공식 문구를 실제 검토한 한국 날짜이며, note에 문구 확인임을 밝힌다. 전체 장소의 확인일은 별도로 `null`을 유지한다. 펫 객실 상품은 숙소 전체의 실내 동반 허용으로 확대하지 않는다. 기존 전화·현장 확인 사실을 덮어쓰지 않는다. 구조화 연구 관찰은 `valueStructured`에 보존하고 화면에는 읽을 수 있는 문장을 제공한다.

`sourceUpdatedAt`는 공급자가 표시한 원본 수정일만 담는다. 실제 수정일을 보지 못했으면 `null`이다. `basicSourceCheckedAt`, `retrievedAt`를 복사하여 정책 확인일을 만들어서는 안 된다. 개별 사실의 `verifiedAt`는 유효한 `YYYY-MM-DD` 달력 날짜를 사용한다.

한국 기준 열람일이 UTC timestamp의 날짜와 다르면 `basicSourceCheckedAt`를 명시한다. 예를 들어 `2026-11-07T19:30:00Z`는 한국에서 11월 8일이므로 원래 timestamp를 보존하면서 기본 정보 열람일은 `2026-11-08`로 기록한다.

## 권역과 태그 분류

권역은 행정구역 자체가 아닌 앱의 탐색 편의를 위한 분류다. 원문 행정구역은 `district`나 별도 관측으로 보존한다.

| 권역 | 현재 분류 기준 |
|---|---|
| 북부 | 제주시 도심 |
| 동부 | 조천·구좌·성산·우도 |
| 서부 | 애월·한림·한경 |
| 남부 | 서귀포 도심·남원·중문·안덕 |

경계 지점은 주소를 직접 확인하여 하나의 권역으로 정하고 변경 이유를 기록한다. 좌표 미확인 상태에서 임의 중심 좌표를 실제 장소 위치로 저장하지 않는다.

| 원문 정보 종류 | 사용 범위 | 판정으로 넘기기 전에 필요한 확인 |
|---|---|---|
| 메뉴·시설·풍경·체험 태그 | 검색·상세의 원문 태그 | 태그만으로 가격·운영 여부를 확정하지 않음 |
| 가족·아이와 함께 | 탐색 참고 | 어린이 출입 가능 여부, 나이 제한, 특정 공간 제한 |
| 반려동물·펫 동반 | 탐색 참고 | 개 동반 여부, 실내/실외, 체급·체중, 포함 경계, 캐리어·추가요금 |
| 무장애·휠체어·접근 난이도 | 탐색 참고와 관측 문장 | 실제 무단차 동선·출입구·화장실 및 적용 구간 |
| 유아의자·주차장 | 해당 시설의 공식 표기 | 제공 여부·제한·현재 사용 가능 여부와 출처·확인일 |
| 어린이 출입불가·반려동물 금지 | 제한 근거 후보 | 전체 시설인지 일부 구역인지와 적용 기간. 넓혀 해석하지 않음 |
| 예약 광고의 최저가·할인가 | 광고 관측 기록만 유지 | 방문 날짜·객실/인원·세금·수수료·변경 조건이 맞는 실제 요금 |

## 이미지와 언어

현재 장소 카드의 식당·카페·숙소 SVG는 사진이 없는 상태를 알리는 카테고리 아이콘이다. `imageKind: "placeholder"`로 구분하며 실제 외관·객실·음식을 표현한 사진이라고 표시하지 않는다. 히어로·브랜드의 생성 이미지를 특정 실존 업체 사진으로 재사용하지 않는다.

실제 사진을 추가하려면 원본 URL, 권리자, 이용 허용 범위, 라이선스, 크레딧을 확인하고 기록해야 한다. 사진 URL이 공개되어 있다는 사실만으로 재게시 권한을 확정하지 않는다. 상세 원문에 번역이 없는 장소명·주소는 원문 표기를 유지한다. 앱 메뉴의 4개 언어 지원을 모든 업체 정보의 번역 완료로 표현하지 않는다.

## 갱신 책임과 운영 전환

- 수집 담당: 공식 페이지를 실제 열람하고 관측 기록·시각·출처를 남긴다.
- 검수 담당: 식별자 중복, 주소·권역, 태그와 사실의 구분, 제한 조건, 사진 권리를 확인한다. 가능하면 수집자와 분리한다.
- 배포 책임자: 승인된 변경만 통합하고 테스트·빌드·배포 결과를 기록한다. 담당자 실명과 인수인계 경로는 운영 시작 전에 지정해야 한다.
- 수정 요청 담당: 신고 근거를 확인하여 원본 관측과 판정 사실을 함께 갱신한다. 접수됐다는 이유만으로 현재 사실을 자동 덮어쓰지 않는다.

기본 목록은 정기적으로 재검토할 대상을 관리하고, 휴폐업·금지 정책·주소 변경 신고는 다음 정기 수집까지 미루지 않는다. 판정 엔진의 운영·정책·시설 확인 주기는 최신성을 판단하는 규칙이며 자동 수집 스케줄이 아니다. 자동 수집 코드가 있어도 실제 실행 예약이나 정책 자동 검증을 활성화한 것은 아니다.

승인된 자동 수집은 공급자의 전체 페이지를 작은 실행 단위로 이어서 읽는다. 실행별 최대 페이지·항목·시간, 중복 방지 lease, 재개 cursor, 원문 hash와 이력을 적용한다. 처리 중 페이지 내용이 바뀌면 해당 페이지에서 이미 처리한 콘텐츠 ID를 건너뛰어 다음 항목으로 진행하고, 변경된 앞부분은 다음 전체 주기에서 다시 확인한다. 누락 1회나 네트워크 실패만으로 장소를 삭제·휴업 처리하지 않는다. 실제 예약 설정·게이트·비용 조건은 [동기화 운영 문서](14_recurring_ingestion.md)에서 관리한다.

`DEMO_MODE=false` 및 `CLOUD_SERVICES_ENABLED=false`에서는 로컬 공식 JSON을 표시한다. `DEMO_MODE=true`는 가상 예제를 명시적으로 선택한다. 클라우드 게이트를 켜면 `sourcePlaces`의 원문 기본목록에 `places`의 게시된 검수 내용을 우선 적용하며, 숨김·휴업·폐업 검수 상태는 기본목록에서 제외한다. 신규 원문은 사실·가격 미확인 및 placeholder 상태로 제공할 수 있어 전부 수동 게시될 때까지 수집 목록을 막지 않는다.

자동 수집은 기존 DB의 검수 사실·가격·사진·게시 상태를 보존한다. 게시 장소의 주소·유형·권역·좌표가 바뀌면 기존 검수값을 유지하고 새 원문 및 검토 필요 상태를 기록한다. 이는 새 위치에 과거 시설·사진 검증을 그대로 붙이는 일을 방지한다. 로컬 `applyCatalogFacts`의 검토 결과가 DB로 자동 이전되는 것은 아니므로 운영 전환 시 이전 범위와 부분 검수 게시 정책을 확인한다. API 키와 서버 비밀값은 수집 JSON, 이 문서, 로그에 포함하지 않는다.
