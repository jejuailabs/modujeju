# 16. 동행별 편의 장치 아이콘과 데이터 확보 계획

작성일: 2026-11-08. 앞부분은 구현된 내용이고, 뒷부분은 아직 실행하지 않은 수집 계획이다.

## 핵심

제주의 많은 스팟 가운데 **아이·반려견·어르신 중 누군가에게 실제로 쓸모 있는 장치가 있는 곳**을 걸러 낸다. 그 장치를 **동행별 아이콘 줄**로 보여준다. 맛집 순위가 아니라 "이 업체에 누구를 위한 무엇이 있는가"를 보여주는 것이 목적이다.

## 구현된 것

### 아이콘 사전 (`src/lib/place-features.ts`의 `featureGroups`)

| 묶음 | 키 |
|---|---|
| 아이 | `highChair` 유아 의자 · `floorSeating` 신발 벗는 좌식 · `stroller` 유모차 출입 · `kidsTableware` 유아 식기·키즈 메뉴 · `nursingRoom` 수유실 · `diaperTable` 기저귀 교환대 · `kidsPlay` 키즈룸·놀이 공간 · `babyBed` 아기 침대·욕조 |
| 반려견 | `petLargeDog` 대형견 가능 · `petAmenity` 펫 메뉴·물그릇 · `petPlayground` 펫 운동장·마당 · `petRoom` 펫 동반 객실 |
| 어르신·휠체어 | `stepFree` 무단차 출입 · `ramp` 경사로 · `elevator` 엘리베이터 · `accessibleToilet` 장애인 화장실 · `tableSeating` 의자·입식 좌석 · `accessibleParking` 장애인·근접 주차 · `wheelchairRental` 휠체어 대여 · `shortWalk` 30분 이내 보행 |
| 공통 | `groundFloor` 1층 이용 · `parking` 매장 주차 · `toilet` 화장실 |

- **신발 벗는 좌식은 아이 묶음에 둔다.** 기어 다니는 아기를 둔 부모가 선호하는 구조이기 때문이다.
- 좌식을 어르신 친화로 추정하지 않는다. 어르신 묶음에는 입식 좌석을 둔다.

### 데이터: `Place.amenities`

판정용 `facts`와 별도로, 검수된 편의 장치를 `amenities[키]`에 기록한다.

```ts
{ value: "yes" | "conditional" | "no" | "unknown",
  source: "official" | "phone" | "onsite" | "search" | "demo",
  verifiedAt: "YYYY-MM-DD" | null,   // 운영진 확인·승인일
  sourceUrl?, publishedAt?, quote?, quantity?, note? }
```

- 우선순위는 `facts` → `amenities` → 원문 관측 순이다. 검수된 판정 사실이 항상 이긴다.
- `amenities`는 동행의 입장 판정(`kidsEntry`, `petEntry`, `stepFree`)을 바꾸지 않는다. 펫 객실이 있어도 반려견 입장은 미확인으로 남는다.
- `search` 근거는 다음 세 가지가 모두 있어야 표시한다. 운영진 승인일, HTTPS 출처, 2025년 이후 게시일.
- 승인일은 365일이 지나면 만료된다. `demo` 근거는 데모 모드에서만 쓴다.
- 검증 스키마는 `amenitiesSchema`(`src/lib/server/place-schema.ts`)다. 운영 DB 경로와 수집 JSON(`research_notes/catalog/*.json`의 `amenities`)이 같은 스키마를 쓴다.

### 화면

- **카드:** 동행별로 한 줄씩 보여준다.
  - 줄 구성: 초상 아이콘, 입장 상태, 확인된 장치 칩(수량 포함, 예: "휠체어 대여 4개").
  - 조건부 칩은 점선 테두리와 "조건 확인" 글자로 구분한다.
  - 미확인 장치는 숨긴다.
  - 입장 불가가 확인된 동행은 줄 대신 제한 칩으로 보여준다(예: "반려견 동반 불가").
  - 장치 확인일 중 가장 최근 날짜를 카드에 표시한다.
- **상세:** 동행 묶음별 타일을 보여준다. 타일을 열면 근거 배지, 확인일, 게시일, 짧은 인용, 출처 링크가 나온다.
  - 근거 배지: 공식 표기 / 전화 확인 / 현장 확인 / 검색 근거·운영진 승인
- **필터:** 동행 3개 아래에 "아이를 위한 시설", "반려견을 위한 시설", "어르신·휠체어를 위한 시설", "공통 편의" 묶음으로 나눈다. 기존 규칙(AND, 조건부 선택 포함, 미확인 제외)을 그대로 따른다.
- 검색 별칭도 추가했다. 예: "수유실", "신발 벗는", "대형견", "경사로".

## 데이터 확보 계획 (아직 실행하지 않음)

1. **명단 확보:** 동행 특화 소스에서 후보 업체를 모은다.
   - 공공: TourAPI 반려동물 동반여행, TourAPI 무장애 여행(유아의자·수유실·유모차 필드 포함), 공공데이터포털 제주 무장애여행정보, 지자체 반려동물 동반출입 음식점 목록, 제주관광공사 반려 여행 DB
   - 민간 앱·사이트(펫온, 멍콕, 맘맘 등)는 **명단 단서로만** 쓰고, 설명이나 속성 목록은 복사하지 않는다. 데이터베이스제작자 권리와 이용약관 때문이다.
2. **기본 정보 보강:** 비짓제주·TourAPI ID와 대조해 사진, 주소, 좌표, 분류를 확보한다. 기존 동기화 엔진을 쓴다.
3. **매일 심층 검색:** 하루 몇 곳씩 "업체명 + 장치 키워드"로 검색한다. 업체 공식 채널이나 2025년 이후 글에서 AI가 장치 키와 인용, URL, 게시일을 추출해 검수 대기열에 넣는다.
4. **검수 후 게시:** 운영진이 장치별로 승인하면 `amenities`에 `source: "search"`로 기록되어 아이콘이 된다. 애매한 항목은 전화 확인으로 넘긴다.

네이버·카카오·구글의 검색 결과와 후기는 저장하지 않는다(`CLAUDE.md`). AI는 근거를 제안할 뿐 사실을 만들지 않는다.

## 1차 검색 조사 결과 (2026-11-08)

- 결과: 신규 78곳을 `research_notes/catalog/companion-spots.json`에 넣었다. 동행별로 아이 32, 반려견 20, 어르신·휠체어 29곳이고 3곳이 겹친다.
- 사진: 모두 비짓제주 상세 페이지와 대조했고, 사진(`companion-photos.json`)을 연결했다. 78개 URL 모두 응답을 확인했다.
- 근거 출처:
  - 아이·반려견: 비짓제주 상세 본문과 태그
  - 어르신: 한국관광공사 열린관광(access.visitkorea.or.kr)의 무장애 편의정보. 수정일 2025-08~2026-11
- 유료 API, 클라우드, 네이버·카카오·구글 출처는 쓰지 않았다.
- 제외한 것:
  - 반려견: "동반 가능"만 있고 실내·야외 구분이 없는 곳. 전화 확인 대상이다.
  - 비짓제주 분류가 관광지인 애견카페·애견펜션
  - 지점이 불분명한 곳, 비짓제주 페이지가 없는 곳
  - 전체 목록은 `research_notes/companion-review-2026-11-08.md` 끝에 있다.
- 한계:
  - 어르신 쪽은 숙소가 0곳이다. 열린관광에 제주 숙소가 없고, 호텔 공식 페이지에서 인용할 문구를 찾지 못했다.
  - 아이 쪽은 기저귀 교환대 0곳, 수유실 1곳이다.
- 근거는 모두 `verifiedAt: null`(승인 전)이라 앱에 아이콘이 보이지 않는다. `node scripts/approve-companion-spots.mjs --all`(또는 ID 지정)로 승인하면 그때부터 아이콘이 켜진다.
